Begrippenlijst IT & cybersecurity

Wat is een scripttaal, een API of een zero-day? Zoek een IT- of securitybegrip op en lees in een paar zinnen wat het betekent. Waar we er een blog over schreven, linken we door naar het hoofdstuk dat het uitlegt.

73 begrippen

Aanvalsoppervlak#

Alle punten waar een aanvaller kan proberen binnen te komen: websites, open poorten, accounts, medewerkers. Hoe kleiner het aanvalsoppervlak, hoe minder kans op een succesvolle aanval.

Active Directory#

De dienst van Microsoft waarmee veel organisaties gebruikers, computers en rechten centraal beheren. Wie Active Directory overneemt, heeft vaak het hele netwerk in handen; daarom is het een vast onderdeel van een interne pentest.

API#

Application Programming Interface: een vaste manier waarop programma's met elkaar praten. Een website of app vraagt bijvoorbeeld via een API gegevens op bij een server. API's zijn een belangrijk onderdeel van een pentest, omdat ze vaak direct bij de data kunnen.

Back-up#

Een reservekopie van gegevens om terug te zetten na een storing, fout of aanval. Een goede back-up staat ook offline of los van het netwerk, zodat ransomware hem niet kan versleutelen, en wordt regelmatig getest.

Besturingssysteem#

De basissoftware die een computer laat werken en andere programma's laat draaien, zoals Windows, macOS, Linux, Android en iOS. Updates van het besturingssysteem dichten vaak belangrijke beveiligingslekken.

Black box, grey box en white box#

Hoeveel de pentester vooraf weet. Black box: niets, net als een buitenstaander. Grey box: een deel, bijvoorbeeld een gewoon gebruikersaccount. White box: alles, inclusief broncode en documentatie.

Broncode (source code)#

De door mensen leesbare code waaruit software bestaat. Wie de broncode heeft, kan zien hoe een programma werkt; daarom krijgt een pentester bij een white-box-test er toegang toe.

Browser#

Het programma waarmee u websites bekijkt, zoals Chrome, Edge, Firefox of Safari. De browser haalt HTML, CSS en JavaScript op en voert die uit op uw eigen apparaat.

Brute force#

Op grote schaal wachtwoorden raden: een computer probeert razendsnel heel veel combinaties of wachtwoorden uit een lijst.

Bug#

Een fout in software waardoor die iets anders doet dan bedoeld. Niet elke bug is een kwetsbaarheid, maar elke kwetsbaarheid in software begint als een bug of een ontwerpfout.

Client-side en server-side#

Waar code draait. Client-side: op het apparaat van de bezoeker, meestal in de browser, en dus aan te passen door een aanvaller. Server-side: op de server die de website host.

Uitleg in onze blogDe beveiligingsvoordelen van statische websitesHoofdstuk: Server-side versus Client-side→
Cloud#

IT-diensten die u via internet afneemt in plaats van op eigen servers te draaien, zoals Microsoft 365, AWS of Azure. De aanbieder beheert de hardware; u blijft zelf verantwoordelijk voor onder meer accounts, rechten en instellingen.

CMS (contentmanagementsysteem)#

Software om de inhoud van een website te beheren zonder te programmeren, zoals WordPress. Een CMS maakt een website dynamisch, en verouderde plugins zijn een veelvoorkomende bron van lekken.

Uitleg in onze blogDe beveiligingsvoordelen van statische websitesHoofdstuk: Als u een CMS gebruikt→
Compiler en interpreter#

Twee manieren om broncode uit te voeren. Een compiler vertaalt de hele code vooraf naar een uitvoerbaar programma (zoals bij C en Go). Een interpreter leest en voert de code uit terwijl het programma draait (zoals bij Python en PHP).

Cookie en sessie#

Na het inloggen onthoudt een website wie u bent met een sessie. Uw browser bewaart daarvoor een sessiecookie: een klein bestandje met een geheime code. Wie die cookie steelt, bijvoorbeeld via XSS, kan als u inloggen zonder wachtwoord.

Credential stuffing#

Inloggegevens uit een eerder datalek uitproberen op andere websites. Werkt omdat veel mensen hetzelfde wachtwoord op meerdere plekken gebruiken.

Cross-site scripting (XSS)#

Een aanvaller laat eigen JavaScript uitvoeren in de browser van een andere bezoeker van een website, bijvoorbeeld om een sessie over te nemen of het slachtoffer te misleiden.

Uitleg in onze blogDe beveiligingsvoordelen van statische websitesHoofdstuk: XSS→
CVE#

Common Vulnerabilities and Exposures: een uniek nummer voor een publiek bekende kwetsbaarheid, zoals CVE-2021-44228 (Log4Shell). Zo praat iedereen over hetzelfde lek.

CVSS#

Common Vulnerability Scoring System: een open standaard van FIRST die de ernst van een kwetsbaarheid uitdrukt in een score van 0,0 tot 10,0, van geen tot kritiek.

Uitleg in onze blogCVSS uitgelegdHoofdstuk: Wat is CVSS?→
CVSS-vector#

De korte tekst achter een CVSS-score, zoals CVSS:3.1/AV:N/AC:L/…, die per onderdeel vastlegt hoe de score tot stand kwam. Zo kan iedereen de score narekenen.

Uitleg in onze blogCVSS uitgelegdHoofdstuk: Hoe wordt de score berekend?→
CWE#

Common Weakness Enumeration: een lijst van soorten fouten, zoals CWE-79 voor XSS. Een CVE is één concreet lek, een CWE is het type fout erachter.

Cyberbeveiligingswet (NIS2)#

De Nederlandse wet die de Europese NIS2-richtlijn (Network and Information Security) uitvoert. Essentiële en belangrijke organisaties moeten hun cybersecurity op orde hebben en kunnen worden gecontroleerd.

Uitleg in onze blogArtikelen 71 & 72 CyberbeveiligingswetHoofdstuk: Valt iedere organisatie onder de Cyberbeveiligingswet?→
Database#

Een georganiseerde opslag van gegevens, zoals klanten, bestellingen of accounts, die een applicatie snel kan doorzoeken. Bekende voorbeelden zijn MySQL, PostgreSQL en Microsoft SQL Server.

DDoS-aanval#

Distributed denial of service: een systeem wordt vanaf veel apparaten tegelijk overspoeld met verkeer, zodat het onbereikbaar wordt voor echte gebruikers.

DNS en domeinnaam#

Een domeinnaam is het leesbare adres van een website, zoals melisitsolutions.com. DNS (Domain Name System) is het 'telefoonboek' van internet dat die naam vertaalt naar het IP-adres van de server.

Dynamische website#

Een website waarvan de server de pagina's per bezoek opbouwt, vaak met een database. Flexibel, maar de server-side code is ook een extra aanvalsoppervlak.

Uitleg in onze blogDe beveiligingsvoordelen van statische websitesHoofdstuk: Wat zijn statische en dynamische websites?→
Ernst (severity)#

Het label bij een CVSS-score: geen (0,0), laag (0,1–3,9), gemiddeld (4,0–6,9), hoog (7,0–8,9) of kritiek (9,0–10,0). Ernst is nog geen risico: dat hangt ook af van uw eigen situatie.

Uitleg in onze blogCVSS uitgelegdHoofdstuk: Van score naar label→
Exploit#

Code of een stappenplan dat een kwetsbaarheid daadwerkelijk misbruikt. Een kwetsbaarheid is de open deur, de exploit is het naar binnen lopen.

Uitleg in onze blogReflected XSS gemeente EindhovenHoofdstuk: (Fixed) exploit→
Firewall#

Een filter tussen netwerken dat bepaalt welk verkeer wel en niet door mag, op basis van vooraf ingestelde regels.

Framework en library#

Kant-en-klare code waarop je verder bouwt, zodat je niet alles zelf hoeft te schrijven. Een library roep je zelf aan voor een taak; een framework (zoals Next.js, Django of Laravel) bepaalt de opbouw van de hele applicatie. Houd ze bijgewerkt: lekken erin raken iedereen die ze gebruikt.

Hash#

Een digitale vingerafdruk van gegevens, zoals een wachtwoord. Dezelfde invoer geeft altijd dezelfde hash, maar uit de hash is de invoer niet terug te rekenen.

Uitleg in onze blogJe wachtwoord is zo sterk als je wachtwoordbeleidHoofdstuk: Wat is een hash?→
Hosting#

Het aanbieden van een website of applicatie op een server die altijd online is. Een hostingpartij verhuurt die serverruimte, zodat u geen eigen server hoeft te beheren.

HTML en CSS#

De bouwstenen van elke webpagina. HTML (HyperText Markup Language) legt de inhoud en structuur vast (koppen, tekst, links, afbeeldingen), CSS (Cascading Style Sheets) bepaalt hoe het eruitziet (kleuren, lettertypes, opmaak). Het zijn geen programmeertalen: ze beschrijven, maar rekenen niet.

HTTP en HTTPS#

HyperText Transfer Protocol: het protocol waarmee uw browser en een website gegevens uitwisselen. HTTPS is de versleutelde variant (de S staat voor Secure) (met TLS): niemand onderweg kan meelezen of iets aanpassen. Het slotje in de adresbalk laat zien dat HTTPS wordt gebruikt.

IP-adres#

Het nummer waarmee een apparaat op een netwerk of internet bereikbaar is, vergelijkbaar met een huisadres. Bijvoorbeeld 192.168.1.10 (IPv4) of een langer IPv6-adres. IP staat voor Internet Protocol.

JavaScript#

De programmeertaal van de browser: hij maakt webpagina's interactief, zoals menu's, formulieren en de CVSS-calculator op deze site. Met Node.js draait JavaScript ook op servers. Bij XSS is het JavaScript van een aanvaller dat in uw browser wordt uitgevoerd.

Kwetsbaarhedenscan#

Een geautomatiseerde scan die systemen controleert op bekende kwetsbaarheden en verouderde software. Snel en breed, maar zonder het menselijke denkwerk van een pentest: een scanner combineert geen lekken en ziet logicafouten vaak niet.

Uitleg in onze blogArtikelen 71 & 72 CyberbeveiligingswetHoofdstuk: Een pentest is meer dan een automatische scan→
Kwetsbaarheid (vulnerability)#

Een zwakke plek in software, hardware of een proces waarmee een aanvaller iets kan doen wat niet de bedoeling is, zoals gegevens inzien, wijzigen of een systeem platleggen.

Linux#

Een open-source besturingssysteem dat op het grootste deel van de servers op internet draait. Pentesters gebruiken vaak een Linux-variant zoals Kali Linux, met veel securitytools ingebouwd.

Malware#

Verzamelnaam voor kwaadaardige software, zoals virussen, spyware en ransomware.

Open source#

Software waarvan de broncode openbaar is, zodat iedereen hem kan inzien, gebruiken en verbeteren. Voorbeelden: Linux, Python en WordPress.

OWASP Top 10#

Een veelgebruikte lijst van de tien belangrijkste risico's voor webapplicaties, opgesteld door de open community OWASP (Open Worldwide Application Security Project). Pentesters koppelen bevindingen er vaak aan.

Patch (beveiligingsupdate)#

Een update die een kwetsbaarheid dicht. Snel patchen is een van de meest effectieve maatregelen, zeker als een lek al actief wordt misbruikt.

Payload#

Het deel van een aanval dat het eigenlijke werk doet, bijvoorbeeld het stukje JavaScript dat een XSS-lek uitvoert in de browser van het slachtoffer.

Uitleg in onze blogReflected XSS gemeente EindhovenHoofdstuk: Payloads maken→
Pentest (penetratietest)#

Een geautoriseerde, gesimuleerde aanval op uw systemen. Een pentester zoekt kwetsbaarheden, probeert ze te misbruiken en rapporteert wat een echte aanvaller zou kunnen bereiken, met advies om het op te lossen.

Uitleg in onze blogArtikelen 71 & 72 CyberbeveiligingswetHoofdstuk: Een pentest is meer dan een automatische scan→
Phishing#

Een nepbericht, meestal een e-mail, dat u probeert te verleiden om op een link te klikken, inloggegevens in te vullen of een bijlage te openen.

PHP#

PHP: Hypertext Preprocessor: een server-side programmeertaal waarop een groot deel van het web draait, waaronder WordPress en veel webshops. Een lek in PHP zelf raakt daardoor heel veel websites tegelijk.

Uitleg in onze blogPHP2Shell: wat betekent dit kritieke PHP-lek?→
Poort#

Een genummerd 'deurtje' op een server waarachter een dienst luistert, zoals 443 voor HTTPS of 22 voor SSH. Elke open poort is een mogelijke ingang; daarom brengt een pentest in kaart welke poorten openstaan.

Privilege escalation#

Een aanvaller met beperkte rechten weet meer rechten te krijgen, bijvoorbeeld van gewone gebruiker naar beheerder.

Programmeertaal#

Een taal met vaste regels waarin je een computer instructies geeft, zoals Python, Java, C# of PHP. De code die je schrijft heet broncode; een compiler of interpreter zet die om naar iets wat de computer kan uitvoeren.

Python#

Een populaire, goed leesbare programmeertaal. Veel gebruikt voor scripts en automatisering, data-analyse, AI en webapplicaties, en door pentesters voor eigen tools en exploits.

Rainbow table#

Een kant-en-klare tabel met de hashes van miljoenen bekende wachtwoorden. Staat een gestolen hash erin, dan is het wachtwoord meteen bekend. Een salt maakt zulke tabellen onbruikbaar.

Uitleg in onze blogJe wachtwoord is zo sterk als je wachtwoordbeleidHoofdstuk: Wat is een salt, en waarom gebruiken we die?→
Ransomware#

Malware die bestanden versleutelt of steelt en losgeld eist. Goede, offline back-ups en snelle updates zijn de belangrijkste verdediging.

Red teaming#

Een realistische aanvalsoefening op de hele organisatie, niet alleen op één systeem. Het red team gebruikt alle middelen van een echte aanvaller, zoals phishing en fysieke toegang, en test ook of de verdediging (het blue team) de aanval opmerkt.

Reflected XSS#

Een vorm van XSS waarbij de kwaadaardige code in een link zit. De website 'weerkaatst' die code terug naar de bezoeker die op de link klikt; er wordt niets opgeslagen op de server.

Uitleg in onze blogReflected XSS gemeente Eindhoven→
Remote code execution (RCE)#

Een aanvaller kan op afstand eigen code laten uitvoeren op uw server. Dit is vaak het ergste soort lek, omdat het neerkomt op volledige controle over het systeem.

Uitleg in onze blogPHP2Shell: wat betekent dit kritieke PHP-lek?Hoofdstuk: Wat is er aan de hand?→
Salt#

Een willekeurige, unieke waarde per gebruiker die vóór het hashen aan het wachtwoord wordt toegevoegd. Daardoor werken kant-en-klare tabellen met hashes niet meer en zijn gelijke wachtwoorden niet te herkennen.

Uitleg in onze blogJe wachtwoord is zo sterk als je wachtwoordbeleidHoofdstuk: Wat is een salt, en waarom gebruiken we die?→
Script#

Een (meestal kort) programma in een scripttaal dat een taak automatiseert, zoals elke nacht een back-up maken of honderd accounts tegelijk aanmaken.

Scripttaal#

Een programmeertaal waarvan de code meestal regel voor regel wordt uitgevoerd door een interpreter, zonder aparte compileerstap. Handig voor automatiseren en snelle aanpassingen. Voorbeelden: Python, JavaScript, PowerShell en Bash.

Server#

Een computer (of programma) die diensten levert aan andere computers, de clients. Denk aan een webserver die websites aanbiedt, een mailserver of een database-server. Een server staat meestal altijd aan en is via het netwerk bereikbaar.

Social engineering#

Mensen manipuleren in plaats van systemen hacken, bijvoorbeeld door je voor te doen als collega of helpdesk. Phishing is de bekendste vorm.

SQL#

Structured Query Language: de taal waarmee je gegevens in een database opvraagt en wijzigt, bijvoorbeeld 'geef alle klanten uit Breda'. Als een applicatie invoer onveilig in SQL plakt, ontstaat SQL-injectie.

SQL-injectie#

Een aanvaller stopt eigen databasecommando's in een invoerveld of URL, omdat de applicatie invoer direct in een databasequery plakt. Gevolg: gegevens uitlezen, wijzigen of verwijderen.

Statische website#

Een website zonder server-side code: alleen vaste HTML-, CSS- en JavaScript-bestanden. Iedere bezoeker krijgt dezelfde pagina's, wat de website snel en veel minder kwetsbaar maakt.

Uitleg in onze blogDe beveiligingsvoordelen van statische websitesHoofdstuk: Wat zijn statische en dynamische websites?→
TLS/SSL-certificaat#

Een digitaal bewijs dat een website is wie hij zegt te zijn, nodig voor HTTPS. TLS (Transport Layer Security) is de opvolger van het verouderde SSL (Secure Sockets Layer); de naam 'SSL-certificaat' wordt nog vaak gebruikt.

Trage hashfunctie (Argon2id, bcrypt)#

Een hashfunctie die bewust veel rekenwerk kost. Bij één keer inloggen merkt u niets, maar een aanvaller die miljarden wachtwoorden wil proberen, wordt flink afgeremd.

Uitleg in onze blogJe wachtwoord is zo sterk als je wachtwoordbeleidHoofdstuk: Waarom een trage hashfunctie?→
Tweestapsverificatie (2FA / MFA)#

Inloggen met iets wat u weet (wachtwoord) én iets wat u hebt, zoals een code op uw telefoon. Een gestolen wachtwoord alleen is dan niet genoeg. 2FA staat voor two-factor authentication, MFA voor multi-factor authentication (twee of meer factoren).

Versiebeheer (Git)#

Een systeem dat elke wijziging in code bijhoudt, zodat je terug kunt naar een eerdere versie en met meerdere mensen tegelijk kunt werken. Git is het bekendste; GitHub en GitLab zijn websites om Git-projecten te delen.

Versleuteling (encryptie)#

Gegevens onleesbaar maken voor iedereen zonder de juiste sleutel. Anders dan een hash is versleuteling terug te draaien, mits u de sleutel hebt.

VPN#

Virtual Private Network: een versleutelde verbinding over internet, bijvoorbeeld om thuis veilig bij het bedrijfsnetwerk te kunnen. Omdat een VPN toegang geeft tot het interne netwerk, is het een geliefd doelwit voor aanvallers.

Wachtwoordbeleid#

De regels waaraan wachtwoorden in een organisatie moeten voldoen, zoals minimale lengte en een zwarte lijst. Goed beleid draait om lengte, niet om ingewikkelde tekens.

Uitleg in onze blogJe wachtwoord is zo sterk als je wachtwoordbeleidHoofdstuk: Wat is een wachtwoordbeleid?→
Wordlist (rockyou.txt)#

Een lijst met veelgebruikte of gelekte wachtwoorden die aanvallers en pentesters gebruiken om te raden. De bekendste is rockyou.txt, uit een datalek in 2009.

Uitleg in onze blogJe wachtwoord is zo sterk als je wachtwoordbeleidHoofdstuk: RockYou: de lijst die iedere hacker kent→
Zero-day#

Een kwetsbaarheid die al misbruikt kan worden voordat de maker ervan weet of een update heeft uitgebracht. De verdediger heeft dus 'nul dagen' gehad om te patchen.
