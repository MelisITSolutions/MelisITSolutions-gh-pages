IT & cybersecurity glossary

What is a scripting language, an API or a zero-day? Look up an IT or security term and read in a few sentences what it means. Where we wrote a blog about it, we link to the chapter that explains it.

73 terms

Active Directory#

Microsoft's service that many organisations use to manage users, computers and permissions centrally. Whoever takes over Active Directory often controls the whole network; that is why it is a standard part of an internal pentest.

API#

Application Programming Interface: a fixed way for programs to talk to each other. A website or app, for example, requests data from a server through an API. APIs are an important part of a pentest, because they often have direct access to the data.

Attack surface#

Every point where an attacker can try to get in: websites, open ports, accounts, employees. The smaller the attack surface, the lower the chance of a successful attack.

Backup#

A spare copy of data to restore after an outage, mistake or attack. A good backup is also kept offline or separate from the network, so ransomware can't encrypt it, and is tested regularly.

Black box, grey box and white box#

How much the pentester knows beforehand. Black box: nothing, just like an outsider. Grey box: some, for example a normal user account. White box: everything, including source code and documentation.

Browser#

The program you use to view websites, such as Chrome, Edge, Firefox or Safari. The browser fetches HTML, CSS and JavaScript and runs them on your own device.

Brute force#

Guessing passwords on a large scale: a computer tries a huge number of combinations or passwords from a list at high speed.

Explained in our blogYour password is only as strong as your password policyChapter: How do attackers get your password?→
Bug#

A mistake in software that makes it do something other than intended. Not every bug is a vulnerability, but every software vulnerability starts as a bug or a design flaw.

Client-side and server-side#

Where code runs. Client-side: on the visitor's device, usually in the browser, and therefore changeable by an attacker. Server-side: on the server that hosts the website.

Explained in our blogExtra security of static websitesChapter: Server-side versus Client-side→
Cloud#

IT services you use over the internet instead of running them on your own servers, such as Microsoft 365, AWS or Azure. The provider manages the hardware; you remain responsible for things like accounts, permissions and settings.

CMS (content management system)#

Software to manage the content of a website without programming, such as WordPress. A CMS makes a website dynamic, and outdated plugins are a common source of flaws.

Explained in our blogExtra security of static websitesChapter: If you use a CMS→
Compiler and interpreter#

Two ways to run source code. A compiler translates all the code beforehand into an executable program (as with C and Go). An interpreter reads and runs the code while the program is running (as with Python and PHP).

Cookie and session#

After you log in, a website remembers who you are with a session. Your browser stores a session cookie for this: a small piece of data with a secret code. Whoever steals that cookie, for example through XSS, can act as you without your password.

Credential stuffing#

Trying login details from an earlier data breach on other websites. It works because many people reuse the same password in several places.

Cross-site scripting (XSS)#

An attacker makes their own JavaScript run in the browser of another visitor of a website, for example to take over a session or mislead the victim.

Explained in our blogExtra security of static websitesChapter: XSS→
CVE#

Common Vulnerabilities and Exposures: a unique number for a publicly known vulnerability, such as CVE-2021-44228 (Log4Shell). That way everyone talks about the same flaw.

CVSS#

Common Vulnerability Scoring System: an open standard by FIRST that expresses the severity of a vulnerability as a score from 0.0 to 10.0, from none to critical.

Explained in our blogCVSS explainedChapter: What is CVSS?→
CVSS vector#

The short string behind a CVSS score, such as CVSS:3.1/AV:N/AC:L/…, that records each part of how the score was reached. That way anyone can recalculate it.

Explained in our blogCVSS explainedChapter: How is the score calculated?→
CWE#

Common Weakness Enumeration: a list of kinds of mistakes, such as CWE-79 for XSS. A CVE is one specific flaw, a CWE is the type of mistake behind it.

Cybersecurity Act (NIS2)#

The Dutch law (Cyberbeveiligingswet) that implements the European NIS2 (Network and Information Security) directive. Essential and important organisations must have their cybersecurity in order and can be inspected.

Explained in our blogArticles 71 & 72 of the Dutch Cybersecurity ActChapter: Does every organization fall under the Cybersecurity Act?→
Database#

An organised store of data, such as customers, orders or accounts, that an application can search quickly. Well-known examples are MySQL, PostgreSQL and Microsoft SQL Server.

DDoS attack#

Distributed denial of service: a system is flooded with traffic from many devices at once, so it becomes unreachable for real users.

DNS and domain name#

A domain name is the readable address of a website, such as melisitsolutions.com. DNS (Domain Name System) is the internet's 'phone book' that translates that name into the server's IP address.

Dynamic website#

A website whose server builds the pages for each visit, often with a database. Flexible, but the server-side code is also an extra attack surface.

Explained in our blogExtra security of static websitesChapter: What are static and dynamic websites?→
Encryption#

Making data unreadable to anyone without the right key. Unlike a hash, encryption can be reversed, as long as you have the key.

Exploit#

Code or a series of steps that actually abuses a vulnerability. The vulnerability is the open door, the exploit is walking through it.

Explained in our blogReflected XSS Municipality of EindhovenChapter: (Fixed) exploit→
Firewall#

A filter between networks that decides which traffic may pass, based on rules set in advance.

Framework and library#

Ready-made code you build on, so you don't have to write everything yourself. You call a library yourself for a task; a framework (such as Next.js, Django or Laravel) sets the structure of the whole application. Keep them updated: flaws in them affect everyone who uses them.

Hash#

A digital fingerprint of data, such as a password. The same input always gives the same hash, but you cannot work out the input from the hash.

Explained in our blogYour password is only as strong as your password policyChapter: What is a hash?→
Hosting#

Making a website or application available on a server that is always online. A hosting provider rents out that server space, so you don't need to manage your own server.

HTML and CSS#

The building blocks of every web page. HTML (HyperText Markup Language) defines the content and structure (headings, text, links, images), CSS (Cascading Style Sheets) decides how it looks (colours, fonts, layout). They are not programming languages: they describe, but don't compute.

HTTP and HTTPS#

HyperText Transfer Protocol: the protocol your browser and a website use to exchange data. HTTPS is the encrypted version (the S stands for Secure) (with TLS): nobody along the way can read along or change anything. The padlock in the address bar shows that HTTPS is in use.

IP address#

The number by which a device can be reached on a network or the internet, similar to a street address. For example 192.168.1.10 (IPv4) or a longer IPv6 address. IP stands for Internet Protocol.

JavaScript#

The programming language of the browser: it makes web pages interactive, such as menus, forms and the CVSS calculator on this site. With Node.js, JavaScript also runs on servers. In XSS, it is an attacker's JavaScript that runs in your browser.

Linux#

An open source operating system that runs most servers on the internet. Pentesters often use a Linux distribution such as Kali Linux, with many security tools built in.

Malware#

Umbrella term for malicious software, such as viruses, spyware and ransomware.

Open source#

Software whose source code is public, so anyone can read, use and improve it. Examples: Linux, Python and WordPress.

Operating system#

The base software that makes a computer work and lets other programs run, such as Windows, macOS, Linux, Android and iOS. Operating system updates often close important security holes.

OWASP Top 10#

A widely used list of the ten most important risks for web applications, published by the open OWASP (Open Worldwide Application Security Project) community. Pentesters often map their findings to it.

Password policy#

The rules that passwords in an organisation must meet, such as a minimum length and a blocklist. Good policy is about length, not complicated characters.

Explained in our blogYour password is only as strong as your password policyChapter: What is a password policy?→
Patch (security update)#

An update that closes a vulnerability. Patching quickly is one of the most effective measures, especially when a flaw is already being exploited.

Explained in our blogPHP2Shell: what does this critical PHP flaw mean?Chapter: What should you do now?→
Payload#

The part of an attack that does the actual work, for example the piece of JavaScript that an XSS flaw runs in the victim's browser.

Explained in our blogReflected XSS Municipality of EindhovenChapter: Creating payloads→
Pentest (penetration test)#

An authorised, simulated attack on your systems. A pentester looks for vulnerabilities, tries to exploit them and reports what a real attacker could achieve, with advice on how to fix it.

Explained in our blogArticles 71 & 72 of the Dutch Cybersecurity ActChapter: A pentest is more than an automated scan→
Phishing#

A fake message, usually an email, that tries to trick you into clicking a link, entering login details or opening an attachment.

PHP#

PHP: Hypertext Preprocessor: a server-side programming language that runs a large part of the web, including WordPress and many web shops. A flaw in PHP itself therefore affects a huge number of websites at once.

Explained in our blogPHP2Shell: what does this critical PHP flaw mean?→
Port#

A numbered 'door' on a server behind which a service listens, such as 443 for HTTPS or 22 for SSH. Every open port is a possible way in; that is why a pentest maps which ports are open.

Privilege escalation#

An attacker with limited rights manages to gain more, for example going from a normal user to administrator.

Programming language#

A language with fixed rules for giving a computer instructions, such as Python, Java, C# or PHP. The code you write is called source code; a compiler or interpreter turns it into something the computer can run.

Python#

A popular, easy-to-read programming language. Widely used for scripts and automation, data analysis, AI and web applications, and by pentesters for their own tools and exploits.

Rainbow table#

A ready-made table with the hashes of millions of known passwords. If a stolen hash is in it, the password is known immediately. A salt makes such tables useless.

Explained in our blogYour password is only as strong as your password policyChapter: What is a salt, and why do we use it?→
Ransomware#

Malware that encrypts or steals files and demands a ransom. Good offline backups and quick updates are the most important defence.

Red teaming#

A realistic attack exercise against the whole organisation, not just one system. The red team uses everything a real attacker would, such as phishing and physical access, and also tests whether the defenders (the blue team) notice the attack.

Reflected XSS#

A type of XSS where the malicious code is in a link. The website 'reflects' that code back to the visitor who clicks the link; nothing is stored on the server.

Explained in our blogReflected XSS Municipality of Eindhoven→
Remote code execution (RCE)#

An attacker can make your server run their own code from a distance. This is often the worst kind of flaw, because it amounts to full control over the system.

Explained in our blogPHP2Shell: what does this critical PHP flaw mean?Chapter: What is going on?→
Salt#

A random, unique value per user that is added to the password before hashing. This stops ready-made tables of hashes from working and hides identical passwords.

Explained in our blogYour password is only as strong as your password policyChapter: What is a salt, and why do we use it?→
Script#

A (usually short) program in a scripting language that automates a task, such as making a backup every night or creating a hundred accounts at once.

Scripting language#

A programming language whose code is usually run line by line by an interpreter, without a separate compile step. Useful for automation and quick changes. Examples: Python, JavaScript, PowerShell and Bash.

Server#

A computer (or program) that provides services to other computers, the clients. Think of a web server that serves websites, a mail server or a database server. A server is usually always on and reachable over the network.

Severity#

The label that goes with a CVSS score: none (0.0), low (0.1–3.9), medium (4.0–6.9), high (7.0–8.9) or critical (9.0–10.0). Severity is not yet risk: that also depends on your own situation.

Explained in our blogCVSS explainedChapter: From score to label→
Slow hash function (Argon2id, bcrypt)#

A hash function that deliberately takes a lot of computing work. You won't notice it when logging in once, but an attacker trying billions of passwords is slowed down considerably.

Explained in our blogYour password is only as strong as your password policyChapter: Why a slow hash function?→
Social engineering#

Manipulating people instead of hacking systems, for example by posing as a colleague or the helpdesk. Phishing is the best-known form.

Source code#

The human-readable code that software is made of. Whoever has the source code can see how a program works; that is why a pentester gets access to it in a white box test.

SQL#

Structured Query Language: the language used to query and change data in a database, for example 'give me all customers from Breda'. When an application pastes input into SQL unsafely, you get SQL injection.

SQL injection#

An attacker slips their own database commands into an input field or URL, because the application pastes input straight into a database query. The result: reading, changing or deleting data.

Static website#

A website without server-side code: only fixed HTML, CSS and JavaScript files. Every visitor gets the same pages, which makes the website fast and far less vulnerable.

Explained in our blogExtra security of static websitesChapter: What are static and dynamic websites?→
TLS/SSL certificate#

A digital proof that a website is who it claims to be, needed for HTTPS. TLS (Transport Layer Security) is the successor of the outdated SSL (Secure Sockets Layer); the name 'SSL certificate' is still widely used.

Two-factor authentication (2FA / MFA)#

Logging in with something you know (a password) and something you have, such as a code on your phone. A stolen password alone is then not enough. MFA stands for multi-factor authentication (two or more factors).

Version control (Git)#

A system that tracks every change to code, so you can go back to an earlier version and several people can work at the same time. Git is the best known; GitHub and GitLab are websites for sharing Git projects.

VPN#

Virtual Private Network: an encrypted connection over the internet, for example to safely reach the company network from home. Because a VPN gives access to the internal network, it is a popular target for attackers.

Vulnerability#

A weakness in software, hardware or a process that lets an attacker do something that was never intended, such as reading or changing data or taking a system down.

Vulnerability scan#

An automated scan that checks systems for known vulnerabilities and outdated software. Fast and broad, but without the human thinking of a pentest: a scanner does not chain flaws together and often misses logic errors.

Explained in our blogArticles 71 & 72 of the Dutch Cybersecurity ActChapter: A pentest is more than an automated scan→
Wordlist (rockyou.txt)#

A list of common or leaked passwords that attackers and pentesters use for guessing. The best known is rockyou.txt, from a data breach in 2009.

Explained in our blogYour password is only as strong as your password policyChapter: RockYou: the list every hacker knows→
Zero-day#

A vulnerability that can be exploited before the vendor knows about it or has released an update. The defenders have had 'zero days' to patch.
