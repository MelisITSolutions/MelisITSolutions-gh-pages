Attack Vector (AV)Where does an attacker need to be to abuse this vulnerability?
Over the internet, from anywhere in the world. The attacker does not need to be in the same building or on the same network.
Only from the same network, such as the same Wi-Fi, the office network or within Bluetooth range. It does not work from the internet.
The attacker must already be able to work on the computer itself: at the keyboard or logged in remotely. Or they get a user to open a file.
The attacker must physically touch the device, for example to plug in a USB stick or open it up.
Attack Complexity (AC)How hard is the attack, because of things the attacker cannot control?
Easy. No special circumstances are needed: the attack works every time.
Hard. The attack only works under certain conditions, for example when the attacker first has to gather information about the target or intercept traffic between two parties.
Privileges Required (PR)Does the attacker need an account or permissions before they can attack?
No. Anyone can do it, without logging in.
A normal user account is enough, such as that of a customer or employee.
The attacker already needs an account with a lot of permissions, such as an administrator.
User Interaction (UI)Does someone other than the attacker have to do something for the attack to succeed?
No. The attack works without any help from a user.
Yes. A user has to do something, such as click a link, open an attachment or install a program.
Scope (S)Does the damage stay within the vulnerable system, or can the attacker use it to reach other systems too?
No. The damage stays within the vulnerable system itself.
Yes. Through this system the attacker can also hit something else, such as a visitor's browser with XSS, or the computer a virtual machine runs on.
Confidentiality (C)Confidentiality: can the attacker see data that should stay secret?
Yes, everything or something very sensitive. For example all customer data or an administrator's password.
A little. The attacker sees some information, but can't choose what, or it is only a small amount.
No. Nothing leaks out.
Integrity (I)Integrity: can the attacker change or forge data?
Yes, everything or something very important. For example all files, or the bank account number on an invoice.
A little. The attacker can change something, but has little control over what, or the consequences are limited.
No. Nothing can be changed.
Availability (A)Availability: can the attacker take the system down or make it unusable?
Yes, completely. Nobody can use the system anymore, or it stays down for as long as the attacker wants.
Partly. The system gets slower or drops out now and then, but remains mostly usable.
No. The system keeps working as normal.
